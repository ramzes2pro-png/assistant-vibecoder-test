СВОДКА ПО ЛИДАМ

Готовый результат на предоставленном файле: результат.json в этой папке.
Он открывается обычным текстовым редактором. Сам результат объяснён в сводка.txt.

Для повторного запуска нужен Python 3.9 или новее. Дополнительных библиотек нет.
Если Python не установлен, скачайте Python 3 с https://www.python.org/downloads/
и установите. На Windows включите опцию Add Python to PATH, если она показана.

MAC
1. Распакуйте архив целиком. Сохраните рядом папки 02-лиды и данные.
2. Откройте приложение «Терминал» (его можно найти поиском Spotlight).
3. Напечатайте python3 и пробел. Перетащите leads.py в окно терминала.
4. Нажмите Enter. В окне появится сводка.

WINDOWS
1. Распакуйте архив целиком.
2. Откройте папку 02-лиды. В адресной строке Проводника напишите cmd и нажмите Enter.
3. Введите: py leads.py
4. Нажмите Enter. Если команда py не найдена, попробуйте: python leads.py

ДРУГОЙ ФАЙЛ
Mac: python3 "/путь/к/leads.py" "/путь/к/лидам.csv"
Windows: py leads.py "C:\папка\лиды.csv"
Используйте свои пути. Имена колонок и разделитель должны совпадать с образцом.
Даты допустимы в двух видах: 19.10.2026 и 2026-10-19. Кодировка CSV — UTF-8.
Телефоны — российские, +7… или 8…, всего 11 цифр.

СОХРАНИТЬ РЕЗУЛЬТАТ
Добавьте в конец команды: > результат-новый.json
На Windows для корректной кириллицы можно сначала выполнить: chcp 65001
Не направляйте вывод в исходный CSV: команда с > перезаписывает указанный файл.

МЕТОДИКА
День — максимальная разобранная дата в файле. Неделя — эта дата и шесть предыдущих.
Это скользящие семь календарных дней, включая дни без лидов.
Телефоны +7/8 приводятся к одному формату. Яндекс/yandex/Я.Директ — платформа Яндекс.
Удаляется только совпадение даты, имени, телефона, источника и бюджета после нормализации.
Повторные обращения одного телефона в разные дни сохранены; отдельно показано число контактов.
Без ID лида нельзя доказать, что обращения в разные дни — одна и та же заявка.
Основное среднее считается по бюджетам >0. Нули и пропуски посчитаны отдельно,
а среднее с нулями выведено как альтернативный сценарий. Значение нуля в CRM неизвестно.
Валюта в CSV не указана — скрипт её не придумывает.
Если данных для среднего нет, выводится null, а не 0.
При неверной строке скрипт выдаёт понятную ошибку и прекращает расчёт.
